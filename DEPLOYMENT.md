# Deploying NextHire

This is the real path from "runs on my laptop" to "runs on the internet."
Three pieces, three homes:

| Piece      | Where                                   | Why                                             |
|------------|------------------------------------------|--------------------------------------------------|
| Database   | MongoDB Atlas (free tier is fine to start)| Managed, backed up, no server to patch           |
| Backend    | Render (or any Docker host)               | `backend/Dockerfile` + `render.yaml` included    |
| Frontend   | Vercel (or Netlify)                       | Static build, `vercel.json` SPA rewrite included |

Total cost to start: **$0/month** (Atlas free tier, Render free/starter web
service, Vercel free tier). You'll want to upgrade off free tiers before
real traffic — see the note at the bottom.

---

## 1. Database — MongoDB Atlas

1. Create a free account at https://www.mongodb.com/cloud/atlas and a new
   free (M0) cluster.
2. **Database Access** → add a database user with a strong generated
   password (not your Atlas login password).
3. **Network Access** → add `0.0.0.0/0` to allow connections from anywhere
   (Render's outbound IPs aren't static on the free tier). If you're on a
   paid Render plan with static IPs, restrict to those instead.
4. **Connect → Drivers** → copy the connection string. It looks like:
   ```
   mongodb+srv://<user>:<password>@<cluster>.mongodb.net/nexthire?retryWrites=true&w=majority
   ```
   Fill in your user/password and keep `/nexthire` as the database name.
   Save this — it's your `MONGODB_URI`.

## 2. Backend — Render

### Option A: one-click via `render.yaml` (recommended)
1. Push this repo to GitHub.
2. In Render, **New → Blueprint**, point it at your repo. It reads
   `render.yaml` at the root and creates the `nexthire-backend` web
   service automatically, with `backend/` as the root directory.
3. Render will ask you to fill in the env vars marked `sync: false`.
   Minimum required to boot:
   - `MONGODB_URI` — from step 1
   - `CLIENT_URL` — your frontend's URL once you have it (step 3); you can
     come back and fill this in after deploying the frontend
   - `JWT_SECRET` is auto-generated by the blueprint — leave it
4. Deploy. Render builds with `npm install` and starts with `npm start`,
   and polls `/api/health` to confirm it's up.

### Option B: Docker, on Render/Railway/Fly.io/your own VPS
```bash
cd backend
docker build -t nexthire-backend .
docker run -p 3000:3000 --env-file .env nexthire-backend
```
Point your host at `backend/Dockerfile`. It exposes port 3000 and has a
built-in `HEALTHCHECK` hitting `/api/health`.

### Required backend env vars (either option)
```
NODE_ENV=production
MONGODB_URI=<from Atlas>
JWT_SECRET=<long random string>
CLIENT_URL=<your deployed frontend URL, e.g. https://nexthire.vercel.app>
```
Optional but recommended for full functionality:
```
SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASS / EMAIL_FROM   # email verification, password reset
CLOUDINARY_CLOUD_NAME / CLOUDINARY_API_KEY / CLOUDINARY_API_SECRET   # resume/photo uploads
ANTHROPIC_API_KEY / LLM_MODEL   # resume ATS scoring + AI mock interviews
```
Without the optional ones, those specific features degrade gracefully
(e.g. resume upload will 501, mock interview scoring falls back to demo
feedback) — the rest of the app still works.

Once deployed, confirm it's alive:
```bash
curl https://<your-backend>.onrender.com/api/health
# {"success":true,"message":"NextHire API is running"}
```

## 3. Frontend — Vercel

1. In Vercel, **New Project**, import the same GitHub repo.
2. **Root Directory**: `frontend`
3. **Build Command**: `npm run build` (default, from `frontend/package.json`)
4. **Output Directory**: `dist` (default for Vite)
5. **Environment Variable**:
   ```
   VITE_API_BASE_URL=https://<your-backend>.onrender.com/api
   ```
6. Deploy. `frontend/vercel.json` is already set up to rewrite all routes
   to `index.html` so client-side routing (React Router) works on refresh
   and deep links — without it you'd get 404s on any route but `/`.

   *(Using Netlify instead? `frontend/public/_redirects` does the same
   job — just set the same env var and build/output settings there.)*

7. Go back to Render and set the backend's `CLIENT_URL` to this Vercel
   URL (comma-separate it if you also keep a staging URL), then redeploy
   the backend so CORS allows requests from your real frontend.

## 4. Seed data + bootstrap an admin

From your machine, pointed at the production database (temporarily set
`MONGODB_URI` in your local `backend/.env` to the Atlas URI, or run these
from wherever the backend is deployed):
```bash
cd backend
npm run seed          # companies, DSA questions, quizzes, interview bank
npm run create-admin  # reads ADMIN_EMAIL / ADMIN_PASSWORD from .env
```
`create-admin` is idempotent — safe to re-run any time you need to
promote another account to admin (just change `ADMIN_EMAIL`).

---

## 5. Post-deploy checklist

- [ ] `curl https://<backend>/api/health` returns `success: true`
- [ ] Frontend loads, and a fresh signup/login round-trips through the
      real backend (not the demo fallback — check you don't see
      "○ DEMO DATA" badges after logging in)
- [ ] `/admin` pages show `● LIVE DATA` when logged in as the bootstrapped
      admin
- [ ] Refreshing the page on a deep link (e.g. `/dsa-sheet`) doesn't 404
- [ ] CORS: no "blocked by CORS policy" errors in the browser console
- [ ] `JWT_SECRET` is a real random value, not the example placeholder
- [ ] `.env` files are not committed to git (already covered by
      `.gitignore`, but double-check before your first push)

## Before you take on real traffic or real user data
This gets you a working, reasonably secure deploy for a small user base.
Before scaling further, budget time for: automated tests, a staging
environment, log/error monitoring (e.g. Sentry), refresh-token rotation
instead of long-lived JWTs, and load-testing the AI-backed endpoints
(mock interviews, resume scoring) since they call an external LLM API per
request and are the most expensive/slow routes in the app.
